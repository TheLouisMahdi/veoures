Privacy & contribution limits

The shared organism is open to visitors without an account. Your accepted changes become part of a public artwork.

What is saved

Tool type, position, accepted time and mutation parameters are saved in the shared database. Letters and words become anatomy, while their original values remain available in the public event API. Browser identity and network hashes are excluded from public events.

Your contribution session

The hosted edition uses a random, secure HttpOnly cookie for up to 30 days. It allows five accepted changes per browser session per UTC day and safe retries without duplicate changes. Previews and cancellation do not use quota. Clearing cookies starts a different session; this is an anonymous art project, not a verified identity service.

A daily one-way network hash supports abuse limits without storing raw IP addresses. Shared networks allow up to 100 accepted changes and 20 newly issued sessions per UTC day, with a short pause between writes. These limits can affect visitors on the same shared connection.

Browser preferences and sound

Local storage remembers this browser's demo state and connection identity. The static local demo never uploads its changes. Sound starts off and loads only after you turn it on. No analytics, advertising scripts or external fonts are included by this application.

Artwork and availability

Shared changes persist across reloads and deployments. The initial public edition preserves up to 10,000 accepted events; contributions pause when that limit is reached. The body remains viewable. The latest 30 traces appear in the inspector.

The hosting platform may process connection information as part of delivering the service. This page describes the VEOURES application; platform policies apply separately.
